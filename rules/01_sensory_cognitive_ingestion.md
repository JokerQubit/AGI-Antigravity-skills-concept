# Layer 1: Cognitive Sensory Ingestion & Sensory Elevation

This document establishes the operational cybernetics, protocols, and execution standards governing Layer 1 of the OmniCognition Labs 12-Layer Neural Chain. Layer 1 operates as the primary cognitive sensory intake of the architecture, filtering high-entropy conversational noise, elevating disorganized directives into world-class technical specifications, and grounding uninitialized workspaces in physical disk reality.

---

## 1. Sensory Ingestion Architecture & Entropy Filtering

### 1.1 The Sensory Intake Problem
In multi-agent cognitive architectures, raw user prompts, external API inputs, and inter-system signals arrive with extreme entropy variance:
- Truncated instructions ("faz aí", "code it", "fix this").
- Vague architectural visions lacking formal boundaries.
- Conflicting assumptions that violate distributed systems physics.
- Greenfield workspaces with zero established documentation or state continuums.

Layer 1 prevents cognitive degradation by acting as an impervious sensory membrane. No low-structure, high-entropy prompt is ever permitted to reach Layer 2 (Socratic Inquest) or Layer 4 (Architecture) without undergoing sensory deconstruction and elevation.

### 1.2 The Mathematical Entropy Classification Model
Layer 1 continuously evaluates the Shannon entropy $H(X)$ and technical density $D_{\text{tech}}(X)$ of incoming user directives:
$$H(X) = -\sum_{i=1}^{n} P(x_i) \log_2 P(x_i)$$
$$D_{\text{tech}}(X) = \frac{\sum \text{Technical Constraint Keywords}}{\text{Total Word Count}}$$

Inputs are mapped into three distinct operational tiers:
1. **Nominal Structure ($H < 0.35, D_{\text{tech}} \ge 0.40$)**: Structured prompt with explicit technical constraints, schemas, performance targets, and boundary conditions. Bypasses Sandstorm elevation and routes directly to Layer 2 premise auditing.
2. **Moderate Sandstorm ($0.35 \le H \le 0.70$)**: Directive contains clear business intent but lacks technical boundaries, interface contracts, error semantics, or formal typing. Triggers automated 3-pillar elevation.
3. **Critical Sandstorm ($H > 0.70$ or Word Count $< 15$)**: Terse, chaotic, or single-phrase prompts that risk satisficing and hallucination. Triggers immediate dispatch of a clean-context Research Specialist (`RES-SAND-01`) for deep domain inference and premise extraction.

## 3. Greenfield Workspace Onboarding & Disk Reality Grounding

### 3.1 Greenfield Reality Detection
When primary intelligence initializes in an unfamiliar directory, Layer 1 checks for the existence of `.state/`. If absent:
- **Greenfield Invariant**: The system is uninitialized. The agent must NEVER emit generic conversational filler ("Hello! How can I help you today?").
- **Physical Reality Grounding**: Acknowledge the physical disk reality: zero state continuums, zero mapped components.
- **Onboarding Trigger**: Solicit the macro-mission and immediately execute `scripts/onboard_project.ps1` to establish:
  1. `.state/corporate_health.json` (Fiduciary burn rate, risk tiers, blocker tracking).
  2. `.state/status.json` (Global operational phase, active sprint tracking).
  3. `.state/ledger/0000_genesis.json` (Cryptographic genesis block).
  4. `.state/neural_map.json` and `.state/project_context.md` (Physical component maps).

### 3.2 Automated Onboarding Execution Protocol
The specialist `ONBOARD-01` executes:
```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\onboard_project.ps1 -ProjectName "<Target>" -Mission "<Goal>"
```
This guarantees that all downstream layers ingest verified, disk-backed state rather than relying on ephemeral LLM memory.

## 4. Premise Extraction & Epistemic Decoupling

### 4.1 Isolating Facts from Assumptions
Layer 1 systematically deconstructs every prompt into:
- **Observed Disk Facts**: Files, directories, git branches, and unit tests confirmed to exist via tool calls (`list_dir`, `view_file`, `grep_search`).
- **User Hypotheses**: User statements regarding performance, bugs, architecture, or requirements that have not yet been empirically verified.
- **Hallucination Vectors**: Implied libraries, non-existent endpoints, or invalid hardware constraints.

### 4.2 Epistemic Labeling Protocol
Every requirement passed downstream to Layer 2 must be labeled:
- `[PROVEN_FACT]`: Backed by physical disk reality or test execution logs.
- `[UNVERIFIED_HYPOTHESIS]`: Awaiting Socratic drill and boundary validation.
- `[FATAL_FALLACY]`: Contradicts known laws of computation, memory limits, or security models. Triggers immediate `[HARD HALT]`.

## 6. Layer 1 to Layer 2 Cognitive Handshake Contract

### 6.1 Downstream Propagation Invariant
State generated by Layer 1 never bypasses Layer 2. The output artifact `.state/sandstorm_elevation_latest.json` serves as the sole input interface to Layer 2 (Socratic Epistemic Inquest). 

### 6.2 Data Schema Validation
Before propagating state to Layer 2, the sensory subsystem verifies:
1. `entropy_tier` is explicitly defined as `nominal`, `moderate_sandstorm`, or `critical_sandstorm`.
2. `domain` matches one of the recognized domain taxonomy classifications.
3. `pillars` contains exactly 3 populated pillars, each detailing gold standards and actionable directives.
4. `executive_action_plan` contains at least 4 non-empty, actionable directives.
5. Ledger transaction `SANDSTORM_PROPOSAL_ELEVATED` is confirmed in `.state/ledger/`.

Failure of any validation check halts execution and prevents downstream epistemic contamination.
