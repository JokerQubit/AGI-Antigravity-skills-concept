# Departmental Runbook: Recursive Dimension Expansion Protocol (`EXP-RUN-01`)

## 1. Trigger Conditions
Mandatory execution whenever designing a new system, creating a product specification, drafting a complex feature roadmap, or decomposing an ambitious user request.

---

## 2. Step-by-Step Execution Protocol

### Step 1: Establish Root Concept [X]
- Formulate the core problem statement or deliverable without superficial jargon.
- Define what constitutes complete mastery of the domain.

### Step 2: Extract Orthogonal Pillars [X_1 to X_n]
- Pillar 1: Visual / Rendering / Interface Presentation
- Pillar 2: Core Mechanical / Computational Dynamics
- Pillar 3: Environmental Perception / Sensory / Acoustic Feedback
- Pillar 4: Structural Integrity / Physical Destruction / Resiliency
- Pillar 5: Concurrency / Distribution / Netcode / State Synchronization

### Step 3: Benchmarking Against Frontier Exemplars [XY_i]
- For every pillar $X_i$, demand:
  *"Who is the undisputed market or scientific leader in this exact dimension? What enables their technical dominance?"*
- Refuse any benchmark that is mediocre, common, or basic. Select only industry-defining references.

### Step 4: Granular Sub-Layer Decomposition [XY_i.j]
- Deconstruct the benchmark into physical, mathematical, and algorithmic layers:
  - Physics equations ($F = m a$, drag coefficients, fluid dynamics).
  - Algorithmic models (raymarching, spatial octrees, deterministic rollback netcode).
  - Material science specifications (acoustic absorption, thermal dissipation, memory alignment).

### Step 5: Production Specification
- Output an expanded, multi-tiered tree that downstream architecture and engineering teams can implement directly with zero ambiguity.
