# Technical Documentation & Open-Source Persuasion Protocol

## Core Directive
When authoring documentation (READMEs, landing pages, release notes), strike a balance between rigorous scientific authority and commercial accessibility. Avoid overly esoteric jargon that alienates developers while maintaining clear, evidence-based technical value.

## 1. Structural Blueprint for High-Conversion READMEs
1. **Hero Header:**
   - Eye-catching banner visual (`assets/banner.jpg`).
   - 1-sentence value proposition focused on outcomes (e.g., "Upgrade your AI agent from fast-thinking probabilistic guessing to deterministic System 2 AGI reasoning").
   - Badges (License, Version, Stars, Antigravity Plugin).
2. **The "Why" (The Problem vs. The Solution):**
   - **Problem:** LLMs hallucinate, rush through tasks, and suffer from context decay.
   - **Solution:** A 5-sector cognitive framework enforcing adversarial reviews, mathematical verification, and autonomous skill expansion.
3. **1-Minute Quickstart:**
   - Copy-paste terminal commands to install and activate.
4. **Key Features & Capabilities (Structured Breakdown):**
   - Highlighting main pillars with clear emojis and concise descriptions.
5. **Architectural Overview:**
   - Accessible summaries of the 5 Neural Sectors without impenetrable math notation.
6. **Call to Action (CTA) & Community:**
   - Contribution guidelines and star request.

## 2. Tone & Vocabulary Rules
- **Replace Esoteric Jargon with Actionable Clarity:**
  - ❌ *“Topological manifold isomorphism via Kullback-Leibler divergence minimization”*
  - ✅ *“Automated stress-testing that proves code stability under extreme scale and edge cases”*
- **Active Voice:** Write in strong, direct, professional developer prose.
- **Visual Scannability:** Use tables, bullet points, code blocks, and GitHub alerts (`> [!TIP]`, `> [!NOTE]`).
